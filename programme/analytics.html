Learning analytics

Every module in the programme has a live analytics view alongside it. They are gathered here so an educator does not have to open four modules to reach four dashboards. Each opens in a new tab.

A dashboard can only show what its module records, and the four modules do not record the same things. The table below states that for each one, so a reading is not made from a measure that was never collected.

The four dashboards

Each opens that module's live analytics view.

Detail 		Timings and unit completion only. This module records a stance and a written justification, never a correct answer — so it sends no score, and the server rejects item events from it. Open dashboard

Reading these dashboards

Three points worth holding on to before a number here turns into a decision about a cohort:

  • First-attempt means first attempt. a1, a2 and a3 each arrive at a single first-attempt verdict per check by a different route — per-check verdicts in the snapshot, a check that locks on answer, and an event log folded to its earliest verdict. A repeat attempt does not overwrite the first in any of them.
  • a4 has no score to show. Asking its dashboard how a cohort performed has no answer, by design. It can say who worked through what, and how long it took.
  • Collection depends on how the module was served. Automatic collection happens when a module is served by the collection server. Opened as a standalone file, a module keeps working and stores to the learner's own browser — a1 to localStorage only, a2 with a learner-initiated CSV export, a3 with a CSV summary and a full JSON record — and its dashboard sees nothing from that session.
