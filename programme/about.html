About

About this programme

Four self-directed e-lessons on humanising learning materials and analytics for new knowledge acquisition, owned by IMLS Learning Design. This site is the catalogue and launcher for them: it holds no learning content of its own, and every module runs where it is deployed.

How the programme is put together

The four modules are non-linear. Nothing gates a later module behind an earlier one, and there is no fixed order to work through them in — a learner sent here for one topic can open that module and nothing else. Between them they carry 25 learning outcomes across 27 sections, designed to take 5 hours 45 minutes in total.

Each module ends in a capstone that puts the module's material against something real from the learner's own school or project, rather than a final quiz. a2's capstone produces an Official Closed brief; a4's produces an eight-step worked plan for a conversation the learner actually has to have.

The catalogue carries every module's outcomes, and its search runs across all 25 of them at once — the quickest way to find which module carries a topic when you know the topic but not the module.

Name and cohort

The catalogue page offers a name and cohort field. Both are optional: every module opens without them, and each module asks for a name itself if it does not arrive with one.

What is saved is stored in the browser it was typed into, on that device, and nowhere else. It is not an account, there is no password, and it does not follow a learner to another machine. Clearing site data for this page removes it.

When a module is opened from this site, a saved name and cohort are passed to it in the link. This is deliberate: browser storage is per-origin, and the modules are served from a different origin than this site, so the two cannot see each other's storage — without this a learner would be asked again on arrival. The receiving module strips those parameters from its address bar the moment it reads them, so a learner who copies the URL out of the bar into a group chat is not handing over their own name and cohort.

Dashboard links are never decorated. Only the four "Open the module" links carry a name and cohort. The analytics dashboards are an educator view and are left exactly as written.

What gets collected

Collection belongs to the modules, not to this site. Each module collects automatically when it is served by the IMLS collection server, and each one's registry record states exactly what it sends — the analytics page puts all four side by side. Opened as a standalone file instead, a module keeps working and stores to the learner's own browser, and nothing reaches a dashboard.

This site behaves the same way. Served by the collection server, it reports that a module was opened from here. Served as a plain static site — which is how it is published — it has no means of sending anything, and nothing leaves the browser.

The registry record

Every module page carries a registry record: its length, its collection behaviour, its owner, the date it entered the registry, and an integrity value. That record is drawn from the materials registry (materials/manifest.yaml), which is the authority on what version of a module is current.

The integrity value is the first 16 characters of that module's SHA-256 — not a security control, just enough to tell two versions of the same module apart when someone asks which one a cohort actually sat.

This site

Seven static pages, no build step, no backend, no accounts. It works with JavaScript switched off, including all eight launch links — search, filtering and the name field are additions on top of a page that is already complete without them. It can be hosted anywhere that serves static files, or opened straight off disk.
